# 0004 — Persistence: Room 2.x → Room 3

**Status:** Accepted (2026-09-13)

## Context

`:network:cache` uses Room 2.8.5 (`androidx.room`) with three DAOs, three entities, a type
converter, an auto-migration from schema 1 to 2, and a `PagingSource` feeding `:rss-reader`.

Room 2.8.5 does publish iOS variants, so a port is technically possible without changing major
version. Room 3 (group `androidx.room3`, 3.0.3 stable as of 2026-09-09) is nevertheless the line
Google develops and the one built around Kotlin Multiplatform and the `SQLiteDriver` API.
Staying on 2.x would mean migrating later anyway, on a codebase that by then also has an iOS
target — a worse moment.

## Decision

Migrate to Room 3 (`androidx.room3` 3.0.3) during **Phase A**, while the project is still
Android-only and the existing gate fully covers the change.

## Scope of the change

The current code is closer to Room 3's shape than a typical Room 2 codebase, which is why this
is an early stage rather than a late one:

- Package rename `androidx.room` → `androidx.room3` across 19 files, plus the artifact and
  Gradle plugin coordinates (`androidx.room` plugin → `androidx.room3`, `room { }` → `room3 { }`).
- `Room.databaseBuilder(context, klass, name)` is replaced by a driver-based builder —
  `BundledSQLiteDriver` from `androidx.sqlite:sqlite-bundled` 2.7.1. This is the same rewrite
  that the KMP port needed anyway, so it happens once.
- All DAO operations become suspend functions. Most already are; only `RoomFeedCategoryDao.addAll`
  and `.clear` are blocking today, and both are already called from a coroutine.
- `room-paging` → `room3-paging`. `PagingSource` usage itself is unchanged.

Nothing in the module touches `SupportSQLiteDatabase`, `InvalidationTracker.Observer`, LiveData,
or kapt, so none of Room 3's other breaking changes apply here.

## Consequences

- **On-device data.** The database file, schema version and auto-migration are unchanged; the
  rename is a Kotlin package rename, not a schema change. Existing installs must still be
  verified by upgrading over a build that has real cached data — the schemas under
  `network/cache/schemas/` stay as they are, and `exportSchema` must keep pointing there.
  `:app:migration` deals with orphaned databases and should be checked against this stage.
- The DAO signature change ripples into `FeedCacheProvider` / `FeedCacheMutator` only if their
  public API changes; it should not, since those are already suspend.
- Room 3 is a separate group from Room 2, so a half-migrated state where both are on the
  classpath compiles. Do not use that as an intermediate step — migrate the module in one go.

## Amendment — A6 as landed (2026-09-20)

The migration is done. Three Room 3 API changes that this record did not anticipate turned up
while doing it; they are recorded here because B5 inherits them.

- **Type converters were renamed.** `androidx.room.TypeConverter` / `TypeConverters` have no
  counterpart in `room3-common`; they are `@ColumnTypeConverter` and `@ColumnTypeConverters`.
  The converter object itself is unchanged.
- **`PagingSource` is no longer a built-in return type.** Room 3 rejects it with *"Not sure how
  to convert the query result to this function's return type … Did you forget to provide a
  `@DaoReturnTypeConverter`?"*. `room3-paging` ships
  `androidx.room3.paging.PagingSourceDaoReturnTypeConverter`, which must be registered with
  `@DaoReturnTypeConverters` on the `@Database`. The DAO signature is unchanged.
- **`room-ktx` has no Room 3 counterpart.** There is no `room3-ktx` artifact, so
  `androidx.room.withTransaction` is gone. The replacement is `RoomDatabase.withWriteTransaction`
  from `room3-runtime` (a wrapper over `useWriterConnection` + `immediateTransaction`).

Two choices made while implementing, both deliberate:

- The builder sets `setQueryCoroutineContext(Dispatchers.IO)` alongside `setDriver`. Room then
  dispatches DAO work itself, so the `withContext(Dispatchers.IO)` wrappers around pure DAO calls
  in `RoomFeedCacheProviderImpl` were removed. The ones in `RoomFeedCacheMutatorImpl` stay —
  they wrap `WpNetworkClient`, not Room.
- The reflective `Room.databaseBuilder(context, klass, name)` overload was kept. The
  `@ConstructedBy` / `RoomDatabaseConstructor` form needs an `expect object`, so it belongs to B5.

Correction to *Scope of the change*: the package rename touched **10** Kotlin files, not 19, plus
`network/cache/build.gradle.kts`, the root `build.gradle.kts` and the version catalog.

Cost of the `BundledSQLiteDriver` decision, measured: `sqlite-bundled-android` 2.7.1 carries
`libsqliteJni.so` at 1.14–1.28 MB for each of four ABIs. `:app` declares no `abiFilters`, so the
debug APK grew from 22 MB to 27 MB; an app bundle adds roughly 1.2 MB per install. Accepted —
it is the driver iOS needs in C2, and it keeps one SQLite build across platforms.

On-device verification passed: a `main` (Room 2.8.5) debug build was installed on an API 37
emulator and populated with 10 categories, 40 channel items across 4 pages and a metadata row at
schema version 2. The Room 3 build was installed over it without uninstalling and launched in
airplane mode. `fetchCategories` failed to resolve the host, the drawer still listed all 10
cached categories, the feed paged through all 4 cached pages before requesting page 5 from the
network, and `user_version` stayed 2. All three tables were byte-identical before and after.
