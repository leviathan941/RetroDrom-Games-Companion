# 0004 — Persistence: Room 2.x → Room 3

**Status:** Accepted (2026-09-13)

## Context

`:network:cache` uses Room 2.8.5 (`androidx.room`) with three DAOs, three entities, a type
converter, an auto-migration from schema 1 to 2, and a `PagingSource` feeding `:rss-reader`.

Room 2.8.5 does publish iOS variants, so a port is technically possible without changing major
version. Room 3 (group `androidx.room3`, 3.0.3 stable as of 2026-09-09) is nevertheless the line
Google develops and the one built around Kotlin Multiplatform and the `SQLiteDriver` API.
Staying on 2.x would mean migrating later anyway, on a codebase that by then also has an iOS
target — a worse moment.

## Decision

Migrate to Room 3 (`androidx.room3` 3.0.3) during **Phase A**, while the project is still
Android-only and the existing gate fully covers the change.

## Scope of the change

The current code is closer to Room 3's shape than a typical Room 2 codebase, which is why this
is an early stage rather than a late one:

- Package rename `androidx.room` → `androidx.room3` across 19 files, plus the artifact and
  Gradle plugin coordinates (`androidx.room` plugin → `androidx.room3`, `room { }` → `room3 { }`).
- `Room.databaseBuilder(context, klass, name)` is replaced by a driver-based builder —
  `BundledSQLiteDriver` from `androidx.sqlite:sqlite-bundled` 2.7.1. This is the same rewrite
  that the KMP port needed anyway, so it happens once.
- All DAO operations become suspend functions. Most already are; only `RoomFeedCategoryDao.addAll`
  and `.clear` are blocking today, and both are already called from a coroutine.
- `room-paging` → `room3-paging`. `PagingSource` usage itself is unchanged.

Nothing in the module touches `SupportSQLiteDatabase`, `InvalidationTracker.Observer`, LiveData,
or kapt, so none of Room 3's other breaking changes apply here.

## Consequences

- **On-device data.** The database file, schema version and auto-migration are unchanged; the
  rename is a Kotlin package rename, not a schema change. Existing installs must still be
  verified by upgrading over a build that has real cached data — the schemas under
  `network/cache/schemas/` stay as they are, and `exportSchema` must keep pointing there.
  `:app:migration` deals with orphaned databases and should be checked against this stage.
- The DAO signature change ripples into `FeedCacheProvider` / `FeedCacheMutator` only if their
  public API changes; it should not, since those are already suspend.
- Room 3 is a separate group from Room 2, so a half-migrated state where both are on the
  classpath compiles. Do not use that as an intermediate step — migrate the module in one go.
